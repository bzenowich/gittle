# gittle — git feature inventory

`gittle` is a minimal reimplementation of git in Nim (target: < 10 kloc), which
keeps compatibility with git's on-disk repository format, speaks the git wire
protocol over ssh only, and implements only the subset of that protocol needed
by the commands we choose to ship.

These documents are the **menu**: a complete enumeration of what upstream git
does today, so that features can be selected in or out deliberately rather than
by accident. Nothing here is a commitment — it is the superset we are cutting
down from.

## Source of this inventory

Generated by reading the git source tree that sits alongside this directory:

- Command roster: `command-list.txt` (git's own authoritative classification).
- Descriptions and options: `Documentation/*.adoc` (`NAME`, `SYNOPSIS`,
  `OPTIONS` sections, with shared `include::` fragments resolved).
- Git version: `v2.55.0-782-g1630431f32` (master, post-2.55).

Counts: 161 commands plus the `git` driver itself, 32 further manual pages that
are documentation rather than commands, and 2,175 distinct option entries once
shared option groups are factored out (they would be ~4,600 if the shared groups
were repeated per command).

Every command and option below is a markdown checkbox, so the whole inventory
can be marked up in place.

## Marks

| Mark | Meaning |
| --- | --- |
| `- [x]` | In scope for gittle v1 (recommended starting point — argue with it) |
| `- [ ]` | Out of scope for v1 |
| `` `[log]` `` | Seen in the agent tool-call logs; 177 entries, 169 of them kept |
| **CUT from v1** | Section banner: every option below it is out of scope, reason inline |

Current recommendation: **56 of 161 commands, 450 of 2,341 option entries.**
The reasoning, the design rules behind it, the budget, and eight open questions
are in **[plan.md](plan.md)** — read that before revising the marks. All ten open questions
are now decided; §6 is a decision record.

Useful greps:

```sh
grep -n '^- \[ \].*`\[log\]`' *.md   # observed in the logs but currently cut
grep -c '^- \[x\]' *.md               # kept count per file
grep -n '^> \*\*CUT'  *.md            # every cut section and its reason
```

Descriptions here are one-sentence summaries written for selection purposes.
They are deliberately lossy — consult `Documentation/git-<cmd>.adoc` before
implementing anything.

## Notation

- Options are listed with their short and long forms joined by `/`, exactly as
  git documents them.
- `<x>` is a required argument, `[<x>]` an optional one.
- Most boolean long options accept a `--no-` prefix; that is noted only where
  the negated form has behavior of its own.
- **shared group** references (e.g. "accepts *diff options*") point at
  `03`–`05` instead of repeating hundreds of lines per command.
- A trailing `[experimental]` marks commands git itself labels EXPERIMENTAL.
